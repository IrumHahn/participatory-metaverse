# 구현과 실제 플레이 검증

## 기존 프로젝트를 출발점으로 쓸 때

산골 온천 예시가 있는 로컬 작업 경로는 `/Users/irun_hahn/Documents/Codex/meta-game`이다. 존재할 때만 참고한다. 이 경로가 없는 환경에서도 이 스킬은 새 프로젝트로 진행할 수 있어야 한다.
- `public/bath/scene.js`: 아바타, 카메라, 효과와 상호작용 시각화
- `public/bath/pool.js`: 이동/깊이 계산
- `spring-server.js`: 로컬 서버의 권위형 방 상태
- `deployment/worker.js`: Cloudflare Durable Object 서버
- `public/landing`: 입장 랜딩

읽기 전에 해당 프로젝트 지침과 현재 상태를 확인한다. 기존 온천에 덮어쓰지 말고 새 콘셉트는 사용자 지정 위치나 별도 디렉터리에서 제작한다. 비밀값·DB·다른 프로젝트 자료를 스캐폴드에 복사하지 않는다. 현재 소스에서 검증된 부분만 재사용하고 버전/기능의 존재를 추정하지 않는다.

## 상태 설계

서버는 방 배정, 정원, 플레이어 ID, 목적지·속도·행동 시각, 공유 오브젝트 상태를 관리한다. 이동 경계, 전환 조건, 행동 빈도를 검증한다. 클라이언트는 공유 시각을 기준으로 이동과 제스처를 보간한다. 렌더링 프레임마다 전체 메시를 전송하지 않는다.

- 입장→이동→행동→복귀를 상태 전환으로 정의한다. 상충하는 행동은 중단하거나 종료 후 실행하도록 명시한다.
- 인사에는 대상 ID와 시작 시각을 공유한다. 카메라 회전은 캐릭터의 인사 방향과 독립시킨다.
- 클릭과 드래그를 포인터 이동량으로 구분한다. 드래그 후 손을 뗄 때 이동 명령이 나가면 안 된다.
- 걷기 위상은 이동 거리에 따라 누적한다. 짧은 서버 업데이트마다 발걸음을 초기화하지 않는다.
- 파동처럼 합쳐지는 효과는 발생 위치·시각으로 합산하되 움직임의 크기를 제한한다.
- 접속 종료/재연결, 정원 초과, 잘못된 메시지 처리를 구현한다.

## 공간과 표현

눈높이 시점과 거리감을 실제 플레이 상태에서 확인한다. 입구, 활동 중심, 가장자리의 휴식 지점을 두고 이동 경로를 확보한다. 오브젝트 개수를 늘리는 것보다 재질·빛·안개·환경음을 맞춰 장소감을 만든다. 360도 돌아보며 뒷면과 이동 가능한 경계를 확인한다.

표정·어깨·손·시선처럼 작은 반응이 행동의 이유를 전달하도록 한다. 효과 오브젝트는 초기 크기·표시 여부를 명시한다. 얼굴 효과가 거대한 기본 구체로 나타나지 않도록 보이는 상태를 엄격히 제어한다. 소리는 사용자 제스처 후 시작하고 끄기 기능을 제공한다.

## 최소 검증 시나리오

선택한 기능에 해당하는 시나리오만 수행한다.
1. 새 입장부터 첫 행동까지 실제 클릭/탭으로 완료한다. 입장 데이터와 렌더링이 준비된 후 조작한다.
2. 클릭 이동, 드래그 회전의 분리, 좌우 보행, 멈춤, 앞뒤옆 외형을 확인한다.
3. 서로 독립된 두 클라이언트에서 A의 이동·인사·공유 행동을 B가 관찰한다. 로컬 NPC로 대체하지 않는다.
4. 정원 N개의 실제 네트워크 연결과 N+1번째 연결을 만들어 방 정책을 확인한다. 이것은 N대 실기기의 그래픽 성능 시험과 다르다.
5. 행동 중 퇴장·재접속, 경계 이동, 취소·복귀를 확인한다. 진단 텍스트와 화면이 일치하는지 본다.
6. PC·모바일 화면, 콘솔 오류, 터치 UI를 확인하고 캡처를 직접 열어 본다. 모바일 뷰포트 검사와 실기기 성능 검사를 구분한다.

완료 보고에는 수행한 시나리오와 미검증 범위를 기록한다. 큰 트래픽 수용량은 시험 없이 보장하지 않는다.

## 공개 범위가 포함될 때

호스팅 사업자와 기존 계정/도메인을 확인한다. 웹소켓 지원 Node 호스트 또는 Durable Object 같은 상태 유지 서버가 필요하다. Cloudflare 예시는 재사용 가능하지만 단일 로비에 모든 방을 넣는 베타와 방별 분산 구조를 구분한다. 연결 동안 실행되는 타이머와 비휴면 소켓의 비용을 검토한다. 규모가 커지면 매칭과 방별 객체, 휴면 가능 여부를 설계한다.

배포에는 필요한 공개 자산만 포함한다. HTTPS 주소에서 랜딩→입장→두 클라이언트 동기화를 확인한다. 작업 컴퓨터를 켜둬야만 동작하는 구성을 독립적으로 운영되는 서비스라고 부르지 않는다.
